Tri fusion : diviser pour régner

Comprendre l'algorithme, sa stabilité et sa complexité avant de le coder sous contrainte.

Progression du cours62 %
3 sections sur 5 · ~12 min restantes

Le principe

Le tri fusion coupe la liste en deux moitiés, trie chaque moitié récursivement, puis fusionne les deux listes triées. La fusion est l'étape clé : elle compare les têtes de file et reconstruit une liste ordonnée.

merge_sort.py
# Complexité : O(n log n) dans tous les cas
def merge_sort(values):
    if len(values) <= 1:
        return values
    mid = len(values) // 2
    left = merge_sort(values[:mid])
    right = merge_sort(values[mid:])
    return merge(left, right)

def merge(left, right):
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:   # <= garantit la stabilité
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    return result + left[i:] + right[j:]

Points clés

  • Stable avec <= à la fusion.
  • O(n log n) garanti, même au pire.
  • O(n) d'espace auxiliaire.

Pièges fréquents

  • Oublier le reste de la liste la plus longue.
  • Utiliser < et casser la stabilité.
  • Copier les sous-listes à chaque appel sans besoin.
À retenir pour le défi : le score récompense la correction, puis le temps CPU médian sur 5 exécutions. Une solution correcte mais lente reste valide, avec moins de points de performance.
